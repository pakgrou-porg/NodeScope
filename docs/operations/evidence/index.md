## Acceptance blockers

The following claims are deliberately **not operationally accepted**: Framework hardware and 72-hour storage qualification, a Docker-capable replica host deployment, dual-replica failure/failback and certificate revocation, backup creation and isolated restore, live magic-link browser E2E, approved runtime streaming, a signed release tag, and Windows MSI qualification. Each is represented in the release ledger with a separate procedure and recovery boundary.

## Maintenance rule

Every future operational evidence record must add or update an index row containing all eight proof fields: **claim and evidence state**, **commit**, **validation command or procedure**, **environment**, **expected and observed result**, **evidence location**, **known limitation**, and **rollback or recovery**. The deterministic [`scripts/verify-operational-evidence-index.sh`](../../../scripts/verify-operational-evidence-index.sh) contract checks that every indexed claim has all eight fields. A local or CI result must never be relabeled as environment validation without named environment evidence.
